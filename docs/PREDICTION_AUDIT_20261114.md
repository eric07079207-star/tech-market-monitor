# 股市預測系統技術審查與改版診斷

審查基準：Git `07c5890`；獨立分支 `research/oos-audit-20261114`。
目的：提高可驗證的樣本外可靠性，而非提高訓練分數。本輪研究不得自動替換正式模型。

## 最值得優化的五個問題

### 1. 高風險：資料隔離與反覆使用測試集

- 原 LSTM 的外層隔離以 `BDay(20)` 推算，未使用標籤實際到期日；美股假日使它不等同20個交易日。
- 內層 `_calibrate_threshold` 使用 `np.array_split` 分列，同日不同股票可能分散在不同塊；內層沒有標籤到期隔離。
- 早停與門檻調整使用同一驗證資料；每天用同類測試期間決定替換，使測試集逐漸成為調參資料。
- 舊評估的 walk-forward 多數基準使用前面各列標籤，即使那些標籤尚未到期。

本輪：修正外層實際到期日排除及多數基準；關閉預設自動替換。獨立研究以日期分組、3折 expanding walk-forward、訓練／機率校準／門檻選擇／測試四分區，均依 `target_date < 下一區開始日` 隔離。LSTM 早停再取訓練區內的時間尾段並隔離。舊內層校準仍屬歷史管線，未冒稱已全面重新驗證，不可自行恢復自動升級。

### 2. 高風險：最佳權重實際未被凍結

`model.state_dict()` 返回張量參照；後面 epochs 會改動同一張量。舊程式可能標示某 epoch 最佳，實際卻保存後續權重。

本輪改為 `deepcopy(model.state_dict())`；研究 LSTM 同樣採深拷貝、梯度裁切、固定種子及 train-only 標準化。既有 `.pt`／scaler／backtest 保持原樣，備份加 SHA-256 驗證。

依據：[PyTorch 官方保存模型說明](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html)。

### 3. 高風險：歷史可得時間與財報可比性

- FRED observation date 不等於公布日，最新修正值也不等於當年已知值。
- 舊基本面成長率取同指標最後兩個 filed values，可能混入季度／累計期間或重複申報。
- KG 目前累積的事件快照，不足以證明所有歷史事件在指定時點已經被系統知悉。
- `_relative_feature` 缺日期時曾選到下一筆，已修正為只取此前資料。

本輪研究只用可由當日收盤資料推導的特徵，未把不可靠的新聞、總經或基本面補成零後硬加。下一階段需要 `published_at / available_at / fiscal_start / fiscal_end / vintage / accession`，並以 as-of join 建立比較期間。Yahoo 最新調整價仍非真正歷史 vintage，本輪明確列為限制。

### 4. 中高風險：倖存者偏差與非平穩特徵

目前只研究現在仍存在的八檔大公司，不代表可交易的歷史全市場。原模型含價格、成交量絕對尺度及股票價格／ETF價格比，可能學到股票或年代，而不是可泛化的訊號。

本輪研究改用報酬、均線乖離、波動、相對成交量、歷史回撤、相對報酬。缺價不向前補；未收盤資料不進訓練。不宣稱消除倖存者偏差，需另建當年成分與退市資料。市場特徵以開發集消融衡量，無效就保留無效結果，不用漂亮故事合理化。

### 5. 中高風險：方向分數不是可執行績效

舊 `model_directional_avg_return` 為重疊標籤的平均帶號報酬，不是淨值曲線。`max_drawdown_proxy` 為最差單次後續報酬，不是真正最大回撤。測試集事後多數類別是診斷上限，不能當成預先可知的策略。

本輪保留舊欄位相容性但修正標示；研究另建次日開盤、長倉／現金、每 h 日調整、每日市價計值、權重漂移、進出成本的淨值曲線。單邊費用5bps＋滑價5bps，另做20bps壓力情境；現金收益和無風險利率暫設0，沒有做空借券假設。機率校準、交易覆蓋率、Brier、ECE和配對區塊 bootstrap 一起報告。

## 本輪實驗設計

- 股票：AAPL、MSFT、NVDA、AMD、META、GOOGL、AMZN、TSLA。
- 歷史始於2013，涵蓋2015–2016、2018、2020、2022與後續多頭；每日取樣，不把重疊序列當獨立樣本。
- 目標1／5／10／20交易日：收盤後生成訊號，下一開盤至 h 個交易日後開盤的報酬方向。
- 每日八檔同屬一個日期組；每期限測試251個日期、2,008列，不宣稱2,008筆獨立觀測。
- 模型：正則化邏輯迴歸、XGBoost、LightGBM、20日序列／24 hidden／4 epochs 的小型 LSTM。
- Optuna：每個樹模型、每期限6個試驗；3折時間序列平均 Log Loss 選參數，非測試準確率。
- LSTM 為固定小型 CPU 候選；不是用6個樹模型試驗來冒稱完整搜尋所有神經網路架構。
- 獨立的校準段做 sigmoid calibration；再以後續獨立段選0.40–0.60的分類門檻。離門檻不足0.05不產生方向交易訊號。
- Buy & Hold為八檔初始等權買入後持有；動能依當時已知20日報酬；QQQ動能僅用過去QQQ報酬；隨機漫步50%為持現基準。
- 隨機漫步50%的分類平手按看多統計，不應解讀為其真的預測上漲；交易保持現金。
- 95%區間按同日股票彙整、20日區塊抽樣500次；尚非多重試驗校正後的上線證據。
- 測試訊號2025-10-01至2026-09-30；最後20日標籤至2026-10-29。**該歷史期曾被舊系統使用，不是全專案從未看過的資料**。本輪只能稱隔離的回溯研究；真正新樣本從新建立、事前鎖定的影子紀錄開始。

## 不立即採用的模型

- Chronos：先確認金融資料的預訓練重疊、計算量與數值目標，否則歷史回測可能把預訓練記憶當泛化能力。參考 [原論文](https://arxiv.org/abs/2403.07815)。
- Transformer／TFT：現有簡單候選尚未建立優勢，先增加架構只會增加試驗選擇偏誤及成本。
- Ensemble：可以下一輪僅用開發集 OOF 預測訂權重，但不可拿本輪測試表挑贏家再宣稱獨立提升。

## 自動化與發布

- 原6小時資料與每日摘要流程不改頻率，不新增AI API呼叫。
- 新 `prediction-research.yml` 每個美股收盤後的 UTC 00:40（台灣08:40，週二至週六）以凍結模型做影子推論及漂移檢查；GitHub 排程可能延遲，不保證分秒準時。
- 完整訓練只允許明確 workflow_dispatch `mode=train`，不每天反覆選模；永不自動提升為正式模型。
- 所有資料寫入共用已有 Actions concurrency lock；提交前同步／重試、40MB上限；失敗開GitHub Issue，保留最後成功快取。
- 模型輕量部署包保存於Git；訓練特徵與完整實驗快照不放入Git（本機研究目錄，雲端訓練則另上傳90日Actions artifact）。資料及模型雜湊記錄於報告。
- 新預測必須在預定進場開盤前產生，禁止補造事後預測；同版本同股票同日紀錄保持第一筆，期滿才填結果。
- 頁面只讀快取，不在手機開頁時訓練，不依賴Mac或Codex維持開啟。

## 影響與剩餘限制

- 不變更原價格、新聞、持倉、KG事件資料，也不以研究預測覆蓋它們。
- 原模型權重、scaler及歷史回測保持；評估摘要會重新計算修正後的基準和覆蓋率，所以部分診斷數字可改變。
- 原模型的內層調參與基本面缺陷尚待後續替換，不因「保留原模型」就變可靠。預設禁止自動提升是隔離措施。
- 新研究沒有證明改善時，不調低標準、修改測試區間或反覆調參尋找漂亮分數。
- 特定八股、單一測試年度、歷史調整價、沒有退市資料都是外推限制。
- 錯誤警報需使用者開啟GitHub通知；系統可監測失敗，無法保證外部資料源或雲端永不故障。

## 後續順序

1. 累積真正事前鎖定、不可重寫的影子預測；以日期區塊而非列數評估樣本。
2. 優先測試更小特徵集；本輪市場特徵消融無提升，不能直接加更多因子。
3. 基本面按財報期間／公告時間／修訂版本重建，再做獨立消融。
4. 建立歷史成分及退市樣本，增加其他資料供應商核對價格與除權息。
5. 預先指定新檢驗時段及多重試驗修正，最後才研究集成或大型模型。
