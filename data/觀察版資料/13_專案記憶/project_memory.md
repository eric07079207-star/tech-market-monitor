# 專案長期記憶

## 專案核心目標

- 將現有科技股監控儀表板進化成可長期累積的金融研究系統。
- 核心不是單純 AI 新聞摘要，而是建立可回測、可驗證、可推理的金融知識圖譜。
- 市場判讀以三層概念為主：`Fact`、`Narrative`、`Market Reaction`。
- 長期方向是 Graph-RAG、事件關聯、敘事量化、結果標記與預測驗證。

## 已確認的系統原則

- `data/cache/` 是正式快取來源，前台與雲端更新流程都讀這裡。
- `data/觀察版資料/` 是人工檢查與資料倉儲整理版，由匯出腳本生成。
- Streamlit 前台盡量只讀快取，避免人為點擊改變正式資料判讀。
- 例行檢查代表：直接檢查、直接修復、直接驗證，完成後再回報，不需再逐項詢問。
- 敏感資訊不得寫入專案記憶、摘要檔或可提交檔案。

## 更新與自動化

- 市場資料與新聞主流程：GitHub Actions 每 6 小時更新。
- AI 摘要：每日 07:00 台灣時間自動生成。
- 持倉頁刷新：頁面開啟時每 5 到 15 分鐘自動刷新。
- 預測成功率驗證：每日一次。
- 模型與規則檢討：每累積約 30 筆正式預測後檢視一次。
- Codex 關閉時，理想狀態仍由 GitHub Actions 維持資料更新。

## 金融知識圖譜重點

- 事實層只保留客觀事件、數據、來源、時間戳與信心。
- 敘事層把情緒與市場敘事轉成數值特徵，不直接保存情緒化語句作為事實。
- 市場反應層保存事件後的實際價格、波動、量能與相對報酬。
- 目前階段仍以資料累積、事件正規化、去重、未來報酬標記與資料品質為先。

## 已確認的資料治理方向

- 無效、缺值過多、格式不合理的資料要清洗或隔離。
- 罕見但可能真實的異常資料，不直接刪除，先進觀察名單。
- 觀察資料採分層保留，並設定保留時間，避免過早污染正式資料。
- 新聞資料需做來源可靠度、重複事件合併、垃圾訊息過濾與關鍵字風險標記。

## 已確認的使用偏好

- 使用繁體中文顯示。
- 儀表板優先直觀、低干擾、可長期閱讀。
- 在不影響結果品質前提下，盡量降低 API 與 token 成本。
- 規則化結果可以先跑，AI 只在真正能增加資訊密度時再介入。

## 2026-07-24｜KG 預測 V2 多因子趨勢觀察

- KG 預測採版本化資料集。V2 使用五因子投票與跨來源門檻；來源不足時顯示資料不足，V1 歷史不得覆寫。

## 2026-07-24｜專案記憶受控寫入流程

- 專案記憶只保存已確認、可回溯且不含敏感資訊的內容。GitHub Actions 僅負責雲端保存與 Word 匯出，不推論聊天決策。

## 2026-07-24｜分層隨機歷史回測與多來源資料方向

- 長期回測採 point-in-time 原則：只使用當日以前可得的事實、新聞、技術與基本面資料，並以後續實際報酬與回撤驗證。

## 2026-07-24｜KG 新聞出版者與跨來源識別修正

- 跨來源確認以原始出版者或官方來源為單位，不以 RSS 聚合站、轉載頁數或 Google 轉址計數。

## 2026-07-24｜SEC point-in-time 基本面歷史資料

- 基本面研究遵守 point-in-time 原則，以 filed_at 作為可用時間。歷史資料不足是正式資料品質狀態，不可用後來財報補寫過去。

## 2026-07-26｜KG 歷史回測資格與因子有效性報告

- KG 回測資格必須可追溯。市場技術分層結果只能描述關聯，不得直接被稱為因果或投資承諾。

## 2026-07-26｜LSTM 基準比較與機率校準

- 模型表現應同時呈現樣本數、基準比較、方向報酬與機率校準，不應用單一成功率作結論。
